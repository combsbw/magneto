# Magneto

PEMF coil controller and monitor on a Seeed XIAO ESP32-S3: a 1 µs-resolution pulse driver with
staged treatment plans, two 49E hall sensors doing the actual field measurement (scope, pulse-shape
fold, FFT), two NTC thermistors running a latched thermal safety gate, and a status RGB + coil LED
that tell the whole story with no phone attached.

The control panel is one web page, published two ways:

- **On the device** - `http://192.168.4.1` on its own Wi-Fi (`Magneto`, open, captive portal), or
  `http://magneto.local` once it joins your home network.
- **Installed app** - https://combsbw.github.io/magneto/ - add it to the Home Screen. The installed
  (https) app reaches the board over a secure WebSocket, `wss://magneto.local/ws` or
  `wss://192.168.4.1/ws`, carrying the same API.

## Hardware

| Function | Default pin | Notes |
|---|---|---|
| Coil drive | GPIO 7 | TC4420 → IRFB4410 low-side, 24 V coil rail. **HIGH = coil on**, idles LOW with a pulldown. Schottky flyback across the coil. |
| 49E hall, coil center | GPIO 1 | ADC1. Sensor fed from 3V3 (5 V would exceed the pin). |
| 49E hall, coil perimeter | GPIO 2 | ADC1 |
| 10k NTC, coil face | GPIO 3 | ADC1, 10k divider to 3V3 |
| 10k NTC, MOSFET | GPIO 4 | ADC1, 10k divider to 3V3 |
| Status RGB R / G / B | GPIO 5 / 6 / 8 | Common anode hardwired to 3V3; series resistor per leg |
| Coil-rim LED | GPIO 9 | Single color, series resistor |

Every pin is remappable from Settings › Pins (hall sensors and thermistors must stay on GPIO 1-9,
the ADC1 pins). Pin changes are refused while the coil runs, and a bad combination falls back to
the defaults instead of bricking the board.

## What it does

- **Drive**: 0.1-250 Hz in 0.1 Hz steps, pulse width from 1 µs, generated by a 1 µs hardware-timer
  ISR. Duty is reported, never set. Wide vertical sliders with per-slider locks and ceilings
  (ceilings only move while the coil is off, and clamp live tuning and every stage).
- **Plans**: up to 5 stages (frequency, pulse width, length, LED color each), an optional repeat of
  a span of stages, timer chips or open-ended runs, and named setups stored on the board so every
  phone sees the same list.
- **Measurement** (the authority - the coil model is a cross-check): 4-channel continuous DMA ADC
  at ~80 kS/s total; per-channel zeroing with holdoff; peak / mean / RMS since clear; a min/max
  decimated scope; a phase-folded pulse profile (sampling-scope style) with the RL model overlaid
  for the microsecond edges; a 4096-point Hann FFT with sub-bin peak, amplitude and SNR; and the
  measured field carried to the target depth through the coil model.
- **Coil tab**: geometry editor (two pancake layers, AWG, open center, insulation) with a scaled
  cross-section drawing, exact loop-sum field model (elliptic integrals), inductance estimate
  (self + Maxwell mutual), RL pulse prediction, induced-E/EMF at depth, and the formulas in MathML.
  Measured L and R override the estimates.
- **Safety**: coil-face and MOSFET temperature limits plus dT/dt limits (defaults 110 °F / 140 °F /
  20 °F/min), °F/°C in the UI. A trip kills the coil, latches across reboots, and needs an explicit
  reset gated on a fresh in-range reading. Both the latch and the probe requirement are
  configurable; bypassing the shutoff is possible and loudly flagged. A stuck-pin watchdog and a
  probe-loss trip back it up.
- **LEDs**: connectivity, update progress/result, idle, running (fixed color, stage colors /
  treatment sweep, or data feedback - temperature or field mapped blue→red), pause, finish and
  trip all have distinct patterns (legend in Settings › Status LEDs). The coil LED mirrors the
  treatment swell and the pause/trip blinks.
- **Update**: one button. The board joins your Wi-Fi, pulls the newest build from this repo's
  `latest` release over verified HTTPS, flashes and restarts - progress and failure reasons on the
  LED. Local upload at `/update` and ArduinoOTA (port 3232) also work.

## Building

```
make deps     # arduino-cli + esp32 core 2.0.17
make build    # compiles ui/app.html -> webui.h, certwindow.h, then the sketch
make flash    # USB
make ota      # over Wi-Fi
make test     # host tests: engine, settings parser, update helpers
make ui       # rebuild webui.h and docs/ after editing ui/app.html
```

`ui/app.html` is the single UI source. `tools/embed_ui.py` gzips it into `webui.h` for the board;
`tools/build_pages.py` wraps it into `docs/` for GitHub Pages (manifest + service worker, offline
capable). CI compiles every push, runs the host tests, verifies `docs/` is current, and refreshes
the `latest` release with `magneto.ota.bin` (update through the page) and `magneto.full.bin`
(first USB flash at 0x0).

GitHub Pages is served from `docs/` on `main` (Settings › Pages › Deploy from a branch).

## iOS and the secure socket

An installed https app may not talk plain http, so the board runs its own certificate authority:
first boot it signs a CA (kept in LittleFS across updates) and a server certificate for
`magneto.local` + `192.168.4.1`. On the phone, open the board's own page once, download the
profile (Settings › Connection), install it, and switch it on under Settings › General › About ›
Certificate Trust Settings. "Test secure link" in the app tells you which step is missing.

## Notes

- The soft AP is open and the API unauthenticated - the device is meant to live on its own network
  or a trusted LAN.
- Field numbers come from the hall sensors. The geometry model exists to carry them to depth, to
  cross-check L/R, and to draw the pulse edges the 10 kS/s sampler cannot see - its ideal-edge
  dB/dt figures are upper bounds and labeled so.
- The washer (ferromagnetic backing) is recorded in the geometry but not modeled; expect the
  measured field to run above the bare-coil model when it is in place.
